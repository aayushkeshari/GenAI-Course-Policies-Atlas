# Data dictionary

> **All data in this project is SYNTHETIC.** Real university names are attached to invented policies and
> statements. Nothing here describes what these schools actually do. The data was generated by
> `src/data/generate.py`. Each institution's name is a real US university from
> `data/reference/real_universities.txt`, matched to the institution's state where possible. Every other value
> (control, Carnegie class, enrollment, courses, policies and statements) is invented and was not taken from that school.

Regenerate with `make data` (seed 2026 by default; `make data SEED=7` for another draw). The same seed
always produces byte-identical files.

| File | Rows | Grain |
|---|---|---|
| `data/raw/institutions.csv` | 150 | one CS department |
| `data/raw/statements.csv` | ~350 (348 at every seed) | one excerpt from an official publication |
| `data/raw/courses.csv` | ~2,000 | one course in one term (plus ~1% exact duplicate rows) |
| `data/raw/ground_truth.json` | — | hidden labels and planted effects. **Analysis code must never read it.** |

## institutions.csv

| Column | Type | Values / notes |
|---|---|---|
| `inst_id` | string | `I001`–`I150`, unique |
| `name` | string | a real US university name from `data/reference/real_universities.txt`, unique, in the same state when the list has one left; nothing else in the row describes that school |
| `state` | string | US postal code |
| `census_region` | string | Northeast, Midwest, South, West (US Census region of `state`) |
| `control` | string | `public`, `private` |
| `carnegie` | string | `R1`, `R2`, `Masters`, `Baccalaureate` |
| `cs_enrollment` | integer | CS students; log-normal around a median that depends on `carnegie` |

## statements.csv

| Column | Type | Values / notes |
|---|---|---|
| `stmt_id` | string | `S0001`…, unique, ordered by institution then date |
| `inst_id` | string | foreign key to institutions.csv; 0–4 statements per institution |
| `pub_type` | string | `policy_page`, `news`, `strategic_plan`, `syllabus_template`, `faq` |
| `pub_date` | string | `YYYY-MM`, from 2023-01 to 2026-10 |
| `text` | string | 2–5 sentences assembled from phrase banks, in random order. Exactly one sentence carries the hidden stance; one sentence per true mention label; the rest are neutral filler |

The stance (−2..+2) and the `mentions_integrity`, `mentions_collaboration` and `mentions_careers` labels are
**not** columns. P2 has to code them from `text`. The true values are only in `ground_truth.json`.

**How the text is built.** Each stance level and each label has 9 phrasings, and there are 18 neutral fillers. The text contains deliberate hard cases:
- **Negations** carry stance. "AI use is not prohibited" is permissive; "No form of AI assistance is acceptable" is prohibitive.
- **Hedges** soften stance ("generally", "may", "probably").
- **AI mentions without a stance** appear in filler sentences, e.g. "Generative AI tools are changing quickly…".
- **Keyword traps** use a label word in an unrelated sense, e.g. "data integrity", or "prepared in collaboration with the campus library". These do not make the label true.

**Dev/held-out split (for ANL-03).** The split is public and by institution. A statement is **held-out** if the numeric part of its `inst_id` is odd (I001, I003, …), and **dev** otherwise. A third of the phrasings in every bank are **reserved**: they appear only in held-out statements. So a coder tuned on the dev half is scored on wording it has never seen.

## courses.csv

| Column | Type | Values / notes |
|---|---|---|
| `course_id` | string | `C0001`…; one course, repeated in each term it runs |
| `inst_id` | string | foreign key to institutions.csv |
| `code` | string | `CS ###`; first digit 1 intro, 2 intermediate, 4 upper, 6 graduate |
| `title` | string | course title |
| `level` | string | `intro`, `intermediate`, `upper`, `graduate`. **Casing is inconsistent** (~10% `Intro`/`INTRO` etc.); lowercase before use |
| `is_se` | boolean | `true`/`false`: a software engineering course (never intro) |
| `term` | string | `F23`, `S24`, `F24`, `S25`, `F25`, `S26`, `F26` (fall + spring, in this order) |
| `policy` | integer or blank | 0 prohibited, 1 limited use, 2 permitted with disclosure, 3 encouraged, 4 integrated/required. **Blank in ~8% of rows** (missing at random) |
| `disclosure_required` | boolean or blank | always `true` at policy 2, `false` at policy 0; blank when policy is blank |
| `assessment_adaptation` | string | `none`, `in_class_exams`, `oral_defense`, `process_logs`, `ai_critique`. Present even when policy is blank |
| `tools_named` | multi-label | semicolon-separated from `chat assistant`, `IDE autocomplete`, `agentic coding tool`; empty at policy 0 and when policy is blank |
| `allowed_uses` | multi-label | semicolon-separated from `explanation`, `debugging`, `code_generation`, `testing`, `writing`; empty at policy 0 and when policy is blank |

**Known mess (deliberate, DATA-12).**
- About 8% of rows have a blank `policy`. In those rows `disclosure_required`, `tools_named` and `allowed_uses` are blank too, because a syllabus with no stated policy lists no allowed uses.
- `level` casing is inconsistent.
- About 1% of rows are exact duplicates, in courses.csv only.
- Some statements mention both integrity concerns and collaboration.

## ground_truth.json (hidden; never read by `src/analysis/`)

| Key | Contents |
|---|---|
| `synthetic`, `note`, `seed`, `generator_version` | provenance; `synthetic` is always `true` |
| `parameters` | the exact generator parameters: `policy_model`, `stance_model`, `label_model`, `use_model`, `tool_model`, `assessment_weights`, `disclosure_prob`, `institutions` (incl. `rhetoric_gap`), `catalog`, `statement_count_mix`, `statement_split`, `phrase_banks` (every phrasing with its hard-case tag and reserved flag), `terms`, `mess` |
| `planted_effects` | a plain-language statement of each planted effect (DATA-06..11, 15–17) with its parameter values |
| `institutions` | per `inst_id`: `inst_effect` (shift on course policy), `stance_latent`, `rhetoric_gap` (null or the mismatch kind) |
| `statements` | per `stmt_id`: `stance` (−2..+2), `mentions_integrity`, `mentions_collaboration`, `mentions_careers`, plus `split` (dev/heldout), `reserved_phrasings` (count) and `hard_cases` (tags present) |
| `courses` | per `course_id`: `course_effect` |
| `course_rows` | per course-term: `latent_score` and the true `policy` (before any value was blanked) |
| `mess` | `missing_policy` (with the blanked true values), `recased_level`, `duplicate_rows` |

## Planted effects (what P2 must recover)

The course policy is the nearest integer (halves up), clipped to 0–4, of:
`1.0 + level_effect + 0.6·is_se + 0.2·term_index + control_effect + inst_effect + course_effect + noise`.
In this formula, `level_effect` is intro −0.7, intermediate 0, upper +0.5, graduate +0.6. `term_index` runs from 0 (F23) to 6 (F26). `control_effect` is 0 for public and private, which is the planted null.

| ID | Effect |
|---|---|
| DATA-06 | intro courses are more restrictive than upper-level courses |
| DATA-07 | SE courses are more permissive than non-SE courses at the same level |
| DATA-08 | permissiveness rises every term |
| DATA-09 | R1 departments have a more positive statement stance |
| DATA-10 | **null**: public vs private has no effect on policy |
| DATA-11 | stance tracks the institution's course policies. Integrity mentions are more common at negative stance; collaboration and careers mentions at positive stance (careers also at R1s) |
| DATA-15 | intro courses allow explanation and debugging, rarely code generation; SE courses are the most likely to allow code generation and testing |
| DATA-16 | the more restrictive the policy, the more in-class exams and oral defenses; process logs and AI critiques mostly at policy ≥ 2 |
| DATA-17 | 15% of institutions (22) have a rhetoric gap: an enthusiastic stance with restrictive courses, or the reverse |
